# Description 模式库

调试 description 时，先判断问题属于哪一类，再套用对应模式改写。
所有模式共用同一个公式：动词开头的短语说清做什么 + 正向触发列举用户真实措辞 + 负向触发排除最容易混淆的邻居。

## 模式：触发不足

特征：用户明确提到了相关任务，但技能没有被调用。

弱："Helper for working with spreadsheets"

强："读取、写入并重排 XLSX/CSV 文件（基于 openpyxl）。当用户提到表格、
Excel、sheet、公式，或想清洗/合并/转换任何表格数据时使用——即使没说
'Excel'。不要用于 Google Sheets（用 sheets-skill）或 PDF。"

要点：触发词要覆盖用户的口语说法，而不只是正式名称。

## 模式：过度触发

特征：技能在不相关的场景被调用。

弱："处理文件"

强：明确限定到一种格式，并显式列出不处理的范围。例如："仅处理 XLSX
和 CSV。不要用于 JSON、YAML 或 PDF。"

## 模式：邻居冲突

特征：多个技能同时匹配，或匹配到了错误的那个。

强：在 description 里点名邻居并划清边界。例如："不要用于 CLAUDE.md
（那是项目记忆文件，加载语义不同）。"

## 模式：描述含糊

特征：description 只说了主题，没说能力。

弱："PDF 助手"

强："从 PDF 中提取文本/表格/表单字段。当用户提到读取、解析、合并、
拆分或填写 PDF 时使用。不要用于 DOCX 或 XLSX。"

要点：用动词短语说清"做什么"，而不是给技能贴标签。
