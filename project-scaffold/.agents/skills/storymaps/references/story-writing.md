# 用户故事写作

## 输出格式

每张卡片只写一个简短标题和一句用户故事：

```yaml
name: "<面向结果的简短标题>"
body: "作为一个[具体角色]，我[想要完成的行为或获得的能力]，[以便获得的用户或业务价值]。"
```

`body` 到用户故事句子为止。不要追加验收标准、Given/When/Then、实现说明、背景、拆分理由或备注。

## 写作规则

- **角色**：写实际受益或采取行动的角色；仅在无法更具体时使用“用户”。不要把系统、服务或开发团队写成用户角色。
- **想要什么**：写用户可观察的行为或能力，不写页面、接口、数据库、框架等实现方案。
- **目的**：写行为带来的结果，不要换一种说法重复“想要什么”。
- **范围**：一句故事只表达一个主要目标。出现多个“并且”“以及”“同时”时，检查是否需要拆解。
- **标题**：使用简短的动宾结构或结果描述，避免“处理”“管理”“相关功能”等无法体现范围的词。
- **语言**：固定使用中文故事句式，使用全角逗号和句号，并保留规定句式。

## 质量检查

写入前确认：

1. 不阅读实现细节也能理解谁获得了什么价值。
2. 行为完成后，用户能观察到结果发生了变化。
3. 目的说明价值，而不是重复行为。
4. 标题与 `body` 表达同一范围。
5. 句子没有携带第二个独立目标。

## 示例

不合格：

```text
作为一个用户，我想要开发搜索 API 和搜索页面，以便完成搜索功能。
```

问题：角色过泛，内容描述技术实现，目的只是重复功能。

合格：

```text
name: "按关键词查找文章"
body: "作为一个内容读者，我想按关键词查找文章，以便快速找到感兴趣的内容。"
```
