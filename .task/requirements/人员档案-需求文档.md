# 人员档案 需求文档

> 原始需求来源：`.task/person.md`
> 文档范围：仅覆盖"食堂从业人员"的人员档案与健康证展示需求。

## 1. 背景与目标

### 1.1 背景

人员维护业务系统已经存在并持续维护从业人员数据。本平台是新建门户，**不承担人员维护职责**，目标是展示对方系统的数据，形成"人"维度的合规查看入口。

人员数据经数据中台落库后统一对外提供，门户与在岗编制、驾驶舱指标**复用同一份落库数据**，避免同一指标在不同页面口径不一致。

### 1.2 目标

- 提供从业人员档案的只读查看能力（食堂经理限本餐厅，后勤主任可看全部餐厅）。
- 提供健康证状态的合规标识，自动识别"即将到期"与"已过期"，保障"持证上岗"可查。

### 1.3 页面模块构成

本页面自上而下包含以下模块：

| 模块 | 说明 |
| --- | --- |
| 概览指标 | 人员与健康证的整体风险概览 |
| 人员档案列表 | 从业人员档案与健康证状态，主体模块 |
| 出入记录 | 员工进出留痕 |
| 库房出入台账 | 原料出入库单据留痕 |

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 从业人员 | 食堂在册人员，本需求范围内唯一的人员类别 |
| 健康证状态 | 正常 / 即将到期 / 已过期，由健康证到期日与当前日期实时计算 |
| 即将到期 | 距到期日不足阈值天数，且尚未到期 |
| 已过期 | 已超过到期日 |
| 数据中台 | 提供已落库人员与健康证数据的唯一数据来源 |
| 数据权限 | 按餐厅范围限制可见数据范围的服务端/平台级权限机制 |
| 出入记录 | 员工进出食堂的留痕记录 |
| 库房出入台账 | 原料出库、领用、调拨、盘点等库存变动单据记录 |

## 3. 角色与权限

| 角色 | 数据范围 | 说明 |
| --- | --- | --- |
| 食堂经理 | 本餐厅从业人员 | 仅能查看本人所在餐饮单位的数据 |
| 后勤主任 | 全部餐厅从业人员 | 可跨餐厅查看 |

### 3.1 权限实现要求

- 权限**通过数据权限承载**，按餐厅范围过滤，不得依赖前端隐藏实现。
- 服务端（或数据权限载体）必须对越权范围返回空结果，不得下发超出范围的数据。
- 健康证、人脸照片属于个人敏感信息，全量数据不得下发给无权限角色。

## 4. 功能需求

### FR-1 页面概览指标

页面顶部展示 4 个概览指标卡，用于快速判断人员与健康证的整体风险。

| 指标 | 统计口径 | 副标说明 |
| --- | --- | --- |
| 人员总数 | 数据权限范围内的人员总数（含离职） | 全校 4 食堂 |
| 在职 | 在职状态为"在职"的人数 | 4 家食堂在编 |
| 健康证临期 | 健康证状态为"即将到期"的人数 | ≤30 天到期 |
| 健康证已过期 | 健康证状态为"已过期"的人数 | 需立即换证 |

- 指标按**当前数据权限范围**统计，与列表数据同源。
- 指标**不随筛选条件变化**，始终统计权限范围内的全量数据。

### FR-2 从业人员列表查看

按数据权限范围展示从业人员列表，默认按健康证有效期排序。

- 排序规则：**无健康证记录（到期日为空）的人员排在最前**；其余按健康证有效期（到期日）升序，到期越早越靠前。
- 列表需能直观区分健康证状态（正常 / 即将到期 / 已过期）。
- 列表每行提供**查看**与**编辑**两个操作入口。

### FR-3 人员档案查看（弹窗）

- 在列表点击"查看"，以**弹窗**形式展示该人员的档案信息与健康证信息，不跳转页面。
- 弹窗字段以数据中台提供范围为准（见第 6 章）。

### FR-4 档案编辑（跳转对方系统）

- 门户**不提供编辑能力**，人员与健康证的维护一律在对方系统完成。
- 在列表点击"编辑"，**跳转到对方系统的对应编辑页面**，并携带该人员标识。
- 跳转地址与参数由对方系统提供；门户不做编辑权限校验，编辑权限由对方系统自身控制。

### FR-5 健康证状态标识

- 依据到期日实时计算状态，**不依赖落库的状态字段**。
- 即将到期与已过期采用可区分的标识方式（如颜色或标签）。
- **到期日字段的文字颜色与健康证状态一致**：正常 / 即将到期 / 已过期 分别使用对应语义色（绿 / 黄 / 红）。

### FR-6 筛选与搜索

| 筛选项 | 取值 | 说明 |
| --- | --- | --- |
| 姓名 | 关键字 | 按姓名搜索 |
| 性别 | 全部 / 男 / 女 | 默认全部 |
| 健康证 | 全部 / 即将到期 / 已过期 | 默认全部 |
| 在职状态 | 全部 / 在职 / 离职 | 默认全部 |

### FR-7 导出

- 导出当前筛选条件下的全部结果（非当前分页）。
- 导出数据的权限范围与列表一致。

### FR-8 出入记录

展示员工进出食堂的留痕记录。

| 项目 | 内容 |
| --- | --- |
| 展示字段 | 食堂、类型、姓名、身份、时间、备注 |
| 类型取值 | 员工进入 / 员工离开 |
| 搜索 | 按姓名 / 身份 / 备注 关键字搜索 |
| 数据范围 | **本期仅包含员工进出**；访客、供应商、监管等非本单人员不在本模块内 |
| 排序 | 见第 9 章待确认（当前实现为日期倒序、同日时间升序） |

### FR-9 库房出入台账

展示原料出入库单据留痕。

| 项目 | 内容 |
| --- | --- |
| 展示字段 | 食堂、单据、类型、库存变动、操作人、时间 |
| 单据字段 | 原料名称 + 数量与用途说明（两行展示） |
| 类型取值 | 预领 / 出库 / 领用 / 调拨 / 盘点 |
| 库存变动 | 展示变动前后数量；出库、领用、调拨、盘点体现扣减结果，预领不改动库存 |
| 搜索 | 按原料 / 类型 / 操作人 关键字搜索 |
| 页面说明 | 出库、领用联动原料库存扣减；盘点按实盘校正；低库存提示补货；全程审计留痕 |

## 5. 判定与预警规则

### 5.1 健康证状态判定

| 状态 | 判定条件 |
| --- | --- |
| 已过期 | 当前日期 > 到期日（到期日次日 00:00 起算为已过期） |
| 即将到期 | 0 ≤ 到期日 − 当前日期 ≤ 30 天 |
| 正常 | 到期日 − 当前日期 > 30 天 |

- **即将到期阈值：暂定 30 天**。实际取值与口径**以对方系统为准**，本文件为暂定值；本期不做配置能力，不按餐厅区分，全租户统一。
- **到期日当天算有效期最后一天**（当日仍为有效，次日进入已过期）。

### 5.2 健康证记录缺失的处理口径（重要）

- 无健康证记录的人员**不做特殊标识**，健康证相关列显示为空。
- **口径边界**：由于上述处理方式，"持证上岗"这项校验**仅对存在健康证记录的人员成立**；未采集或无证人员在门户中不体现异常。
- **验收时不得按"全员持证"解读本功能**，本功能不承诺无证人员的检出能力。

## 7. 数据来源与口径

| 项目 | 约定 |
| --- | --- |
| 数据来源 | 数据中台已落库数据，单一来源 |
| 读写边界 | 门户只读，不落库、不维护人员与健康证数据；编辑能力由对方系统提供，门户仅做跳转 |
| 数据粒度 | 仅当前状态快照，无历史记录 |
| 同源关系 | 在岗编制、驾驶舱指标复用同一份落库数据 |
| 人员归属 | 以中台为准，一人一餐厅（当前归属） |
| 状态计算 | 健康证状态由门户按到期日实时计算 |
| 刷新时效 | 本期不承诺刷新时效（原需求中"1 分钟更新"不作为约束） |
| 出入记录来源 | 待确认（见第 9 章），本文件不假设 |

## 8. 来源依据

原始需求原文（`person.md`）：

- 需求：人员档案。从业人员合规档案底座：作为食堂运营"人"维度的核心底座，承载从业人员档案、健康证、在岗情况的全生命周期管理；与在岗编制、驾驶舱指标同源，是食安合规的人员数据根。
- 健康证管理：从业人员健康证全生命周期管理，自动识别临期与过期并预警，保障"持证上岗"。
- 背景说明：人家已经有该人员维护的业务系统，这个是一个新平台，比如门户，要展示对方的数据。
- 角色：食堂经理（只能看本餐厅的人员）、后勤主任（看全部餐厅的人员）。

> 注：上引原文使用临期、过期的表述，本文档统一采用即将到期、已过期作为健康证状态名称，两者含义一致。

## 10. 已知风险

| 风险 | 说明 |
| --- | --- |
| 无证人员不可见 | 按 5.2 口径，健康证记录缺失的人员在门户中显示为空，无法通过本功能识别"无证上岗" |
