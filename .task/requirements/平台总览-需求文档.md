# 平台总览（工作台） 需求文档

> 原始需求来源：`.task/platform-view.md`
> 形态参考：用户提供的两张设计参考图（工作台整体骨架、餐厅"运营下钻"面板）
> 文档范围：仅覆盖"平台总览（工作台）"页面的**展示与跳转**需求；被跳转的业务系统自身功能不在本文件范围内。
> 原型文件：`.task/prototype/平台总览-工作台原型.html`

## 1. 背景与目标

### 1.1 背景

平台是新建门户，各食堂业务（食堂运营、经营分析、合规巡检、中心考核、维修工单、智能预警、人员档案等）均已或将在其他系统中承载。平台总览（工作台）**不是业务处理系统**，而是全局运营与工作入口：汇总全校食堂运营情况、经营模式、平台接入情况、系统健康状态、风险待办与公告信息，并提供核心业务的统一跳转入口。

页面形态按参考图确定为三层骨架：**Hero 汇总区 → 经营模式分布与食堂卡片区 → 平台运行状态 / 风险与待办 / 公告与快捷入口**；单食堂的详细信息通过**右侧"运营下钻"抽屉**呈现，"下钻"与"跳转"是本页面仅有的两种深入方式。

### 1.2 目标

- 提供"全校食堂运营情况"的**一屏概览**，支撑管理者快速判断整体运行与风险水平。
- 以**经营模式**（自营 / 委托承包 / 合作经营）为全局分组维度，呈现各模式的家数与占比，并支持下钻查看各食堂的承包方与合同履约状态。
- 集中呈现**风险与待办**（未闭环预警、巡检整改、维修工单）并直达对应业务处理入口。
- 呈现**平台运行状态**（平台用户、接入组织、边缘网关、设备在线），支撑平台自身的运维可见性。
- 提供**公告**与**核心业务快捷入口**，作为全校用户的统一工作起点。
- 页面按**当前角色的数据权限范围**自适应：后勤主任看全校，食堂经理看本餐厅。

### 1.3 页面模块构成

本页面自上而下包含以下模块：

| 模块 | 说明 |
| --- | --- |
| Hero 汇总区 | 页面标题、范围说明、经营模式分布概览 |
| 经营模式分布 | 自营 / 委托承包 / 合作经营 三个 Tab，含家数与占比（P0） |
| 食堂卡片区 | 当前模式下各食堂的卡片列表（含当日运营对比），支持翻页与下钻 |
| 平台运行状态 | 平台用户 / 接入组织 / 边缘网关 / 设备在线 |
| 风险与待办 | 未闭环预警 / 巡检整改 / 维修工单，含业务处理入口 |
| 公告 | 最新公告列表 |
| 快捷入口 | 6 个核心业务入口 |
| 运营下钻（抽屉） | 单食堂的运营详情、今日预约、就餐趋势与未闭环预警 |
| 平台用户弹窗 | 点击"平台用户"指标卡打开的平台账号明细（参考图引入） |

> 说明：`平台运行状态` 对食堂经理角色**整行隐藏**（见 3.2）。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 工作台 / 平台总览 | 本页面，平台的全局概览与统一入口 |
| 经营模式 | 食堂的经营归属方式，取值为 自营 / 委托承包 / 合作经营，是全局通用筛选维度 |
| 自营 | 由学校后勤自行经营，无承包方 |
| 委托承包 | 委托外部餐饮企业承包经营 |
| 合作经营 | 与外部合作方联合经营 |
| 承包方 | 受委托或合作的经营主体名称，自营食堂无承包方 |
| 合同履约状态 | 承包/合作合同的履约情况：正常 / 即将到期 / 已逾期 / 已终止；自营食堂无合同，统一显示"正常"（见 5.2） |
| 食堂状态 | 食堂当前营业情况：营业中 / 维护中 / 停业 |
| 平台用户 | 人员档案中在职且具备平台登录权限的人数 |
| 接入组织 | 已接入平台的食堂数量（按组织类型分别计数） |
| 边缘网关 | **一台独立设备**（不是设备分类），承载现场设备接入能力；其 CPU、内存等运行指标属于该机器自身 |
| 设备在线 | 除边缘网关外的现场终端设备在线情况（在线数 / 总数） |
| 未闭环预警 | 智能预警中尚未处理闭环的预警条数 |
| 巡检整改 | 合规巡检产生的待处理整改单条数 |
| 维修工单 | 待派单 / 处理中的维修工单条数 |
| 快捷入口 | 工作台上指向其他业务系统的跳转位 |
| 运营下钻 | 从食堂卡片打开的右侧抽屉，展示单食堂的运营详情 |

## 3. 角色与权限

| 角色 | 数据范围 | 说明 |
| --- | --- | --- |
| 后勤主任 | 全部食堂 | 可跨食堂查看全校数据 |
| 食堂经理 | 本餐厅 | 仅能查看本人所在餐饮单位的数据 |
| 采购员 | 待确认（预计同"本餐厅"范围） | 餐厅级角色；本期未定义其在工作台的数据范围 |
| 运维人员 | 待确认（预计为平台级，不含业务数据） | 平台级角色；本期未定义其在工作台的数据范围 |

> 平台角色字典（需求方确认）：**后勤主任 / 食堂经理 / 采购员 / 运维人员**。其中仅前两个角色的数据范围与工作台可见性已定义（见 3.2）。

### 3.1 权限实现要求

- 权限**通过数据权限承载**，按食堂范围过滤，不得依赖前端隐藏实现。
- 服务端（或数据权限载体）必须对越权范围返回空结果，不得下发超出范围的数据。
- 页面的**筛选维度、卡片、计数、占比分母、趋势、预约、预警列表**全部按同一数据权限范围收敛。

### 3.2 模块级可见性

| 模块 | 后勤主任 | 食堂经理 |
| --- | --- | --- |
| Hero 汇总区 | 可见（显示占比概览） | 可见（**隐藏占比**，仅显示家数） |
| 经营模式分布 Tab | 可见，三个 Tab 均带家数与占比 | 可见，**不带占比**；本餐厅所属模式之外的 Tab 显示 `0 家` 并置灰 |
| 食堂卡片区 | 可见，全校食堂 | 可见，**仅本餐厅 1 张卡片**，翻页控件隐藏 |
| 平台运行状态 | 可见 | **整行隐藏**（平台级信息，与食堂经理职责无关） |
| 平台用户弹窗 | 可见（点击"平台用户"指标卡打开） | **不可见**（该卡随"平台运行状态"整行隐藏，无入口） |
| 风险与待办 | 可见，全校口径 | 可见，**本餐厅口径** |
| 公告 / 快捷入口 | 可见 | 可见 |

> 说明：`采购员`、`运维人员` 的数据范围与模块可见性**本期未定义**，暂不纳入本矩阵。**在两个角色的规则确认前，工作台不对其开放**（否则会出现越权访问平台级信息的风险，见第 10 章）。

## 4. 功能需求

### FR-1 Hero 汇总区

- 展示页面标题与范围说明，右侧展示经营模式分布概览。
- 后勤主任：标题为 `全校食堂运营总览`，副标为 `今日实时 · 一屏统揽 N 家食堂`（N 为权限范围内食堂数）；右侧为分布概览，如 `全校 10 家食堂 · 自营 50% / 委托承包 30% / 合作经营 20%`。
- 食堂经理：标题为 `{本餐厅名称} · 运营总览`，副标为 `本餐厅实时`；右侧**只显示家数**（`食堂 1 家`），**不显示占比**。
- Hero 区不接受点击，不承载跳转。

### FR-2 经营模式分布（P0）

- 以 `自营 / 委托承包 / 合作经营` 三个 Tab 呈现，**默认选中"自营"**。
- 每个 Tab 展示该模式的**家数**；后勤主任视角同时展示**占比**，形式为 `自营 5 家 · 50%`。
- Tab 计数与占比按**当前角色可见范围的食堂总数**计算，分母口径见 5.1。
- **无食堂的模式 Tab 始终显示**（不隐藏），显示 `0 家` 并置灰不可点击。
- 切换 Tab 时，食堂卡片区展示该模式下的食堂，翻页回到第 1 页。
- 经营模式同时作为**全平台通用筛选维度**：本页面通过 Tab 生效；其他业务页面（营收、人次、投诉、食安检查结果按经营模式分组对比）是否铺开，见待确认清单。

### FR-3 食堂卡片区

- 展示当前 Tab 对应模式下、当前权限范围内的食堂卡片，**每页 4 张**，**横向滑动翻页**。
- 翻页控件：左右箭头（Secondary Toolbar 规格）+ `当前页/总页数` 文本指示。
- 食堂总数 ≤ 4 时，**隐藏翻页控件**；最后一页不足 4 张时**左对齐排列，不补空白占位卡**。
- 卡片承载**各食堂当日运营对比**（`今日营收` / `今日就餐` / `今日投诉`，口径见 5.5），用于横向比较各食堂当日表现。
- **卡片上不展示待办计数**（未闭环预警 / 巡检整改 / 维修工单）；三类待办统一在 FR-5"风险与待办"行展示，避免同一指标在页面上出现两次。
- 卡片字段清单见 6.3。
- 点击卡片任意位置打开**"运营下钻"抽屉**（见 FR-4）；点击不跳转页面。

### FR-4 食堂运营下钻（右侧抽屉）

- 以**右侧抽屉**形式展示单食堂详情，不跳转页面。抽屉宽度 600–720px，含遮罩，支持"关闭按钮 / 点击遮罩 / Esc"三种关闭方式。
- 抽屉由上至下包含：标题区 → 基本信息 → 今日预约 → 近 7 日就餐趋势 → 未闭环预警。
- 标题区：`{食堂名称} · 运营下钻`，副标为 `{经营模式} · {食堂状态} · 卫生等级 {X}`。
- **基本信息区展示承包方与合同履约状态**，这是需求 P0 要求的"下钻查看各食堂的承包方与合同履约状态"的落点。
- 抽屉内容按数据权限过滤：食堂经理只能打开本餐厅卡片。
- 抽屉为**只读**，不提供编辑能力。

### FR-5 风险与待办

- 独立成行，展示 3 张卡片：`未闭环预警`、`巡检整改`、`维修工单`。
- 每张卡片展示：名称、数量、副标说明、`查看全部` 入口。
- 点击 `查看全部` **跳转到对应业务系统**，并携带当前数据权限范围；跳转地址与参数由对方系统提供（见待确认清单）。
- 本模块**只做汇总与跳转，不承载就地处理**（闭环、派单、整改确认均在对应业务系统完成）。
- 三类待办**只在"风险与待办"行展示**，**不在食堂卡片上重复展示**，避免同一指标在页面上出现两次。

### FR-6 平台运行状态

- 展示 4 个指标卡：`平台用户`、`接入组织`、`边缘网关`、`设备在线`。
- **边缘网关按"一台独立机器"计数**（在线台数 / 总台数），不做设备分类统计；网关的 CPU、内存等运行指标属于该机器自身。
- 指标口径见 6.4；本模块对食堂经理**整行隐藏**。
- `系统健康情况` 本期不做（见待确认清单）。

### FR-7 公告

- 展示最新公告 3–5 条，字段为 `类型标签` + `标题` + `发布时间`。
- 提供 `更多` 入口。
- 点击公告条目跳转到公告详情；跳转地址见待确认清单。

### FR-8 快捷入口

- 展示 6 个入口：`食堂运营`、`经营分析`、`合规巡检`、`中心考核`、`维修工单`、`智能预警`。
- 每项为"图标 + 名称"，点击**跳转到对应业务系统**。
- **不含"人员合规"**（其已在一级导航中，避免重复）。
- 跳转地址与参数由对方系统提供（见待确认清单）。

### FR-9 平台用户查看（弹窗）

- 点击**"平台运行状态"中的"平台用户"指标卡**打开"平台用户"弹窗，以**居中弹窗**展示平台账号明细，不跳转页面。该指标卡为可点击状态（悬停高亮），是本弹窗的**唯一入口**。
- 弹窗顶部提供筛选：`搜索姓名 / 账号`、`全部角色`、`全部状态`（默认全部）。
- 列表字段见 6.9；底部展示账号总数。
- 关闭方式：关闭按钮 / 点击遮罩 / Esc。
- 弹窗为**只读**：不提供新增、编辑、启停账号的能力；账号维护是否在本平台承载见待确认清单。
- **可见性**：仅平台管理侧角色可见；食堂经理视角下"平台运行状态"整行隐藏，**没有该入口**（见 3.2）。

## 5. 判定与口径规则

### 5.1 经营模式占比口径

| 项目 | 口径 |
| --- | --- |
| 统计粒度 | **食堂**（不按档口、不按经营单元） |
| 分母 | **当前角色可见范围内的食堂总数**（后勤主任=全校，食堂经理=本餐厅） |
| 分子 | 该经营模式下的食堂家数 |
| 占比展示 | 家数 + 百分比；食堂经理视角**不展示百分比** |
| 主展示 | **按家数占比**；营收、人次、投诉、食安检查结果的按模式分组对比属其他页面，本页面不做归一化 |

- `停业` 食堂**计入分母**，仅在卡片上以食堂状态区分；`未接入平台` 的食堂不在本页面范围内（是否计入分母见待确认清单）。
- 占比与家数**不随 Tab 切换或翻页变化**，始终为权限范围内的全量统计。

### 5.2 合同履约状态判定

| 状态 | 判定条件 |
| --- | --- |
| 已终止 | 合同已终止/解除，未续签 |
| 已逾期 | 当前日期 > 合同结束日期，且未续签 |
| 即将到期 | 0 ≤ 合同结束日期 − 当前日期 ≤ 阈值天数 |
| 正常 | 合同结束日期 − 当前日期 > 阈值天数；**自营食堂无合同，统一按"正常"展示** |

- **即将到期阈值暂定 90 天**，实际取值**以合同管理归属系统为准**，本文件为暂定值；本期不做配置能力。
- 合同结束日当天算有效期内最后一天。
- 自营食堂无承包方、无合同，履约状态**统一显示"正常"**，**页面任何位置都不出现"不适用"状态**。
- 该"正常"是**"无合同可违约"的默认展示口径**，不代表自营食堂存在合同，也不代表合同履约良好；相关误读风险见第 10 章。

### 5.3 食堂状态

| 状态 | 语义 |
| --- | --- |
| 营业中 | 正常对外供餐 |
| 维护中 | 暂停供餐，进行设备/场地维护 |
| 停业 | 已停止经营 |

- 食堂状态为**需求外保留项**（原始需求未描述），保留原因：经营模式占比需要区分"停业"与"未接入"，否则占比会被失真。

### 5.4 待办计数口径

- `未闭环预警`、`巡检整改`、`维修工单` 三类**并列、互不包含**，不加总为单一数字。
- 主页面**不使用"告警"作为指标名**，统一使用"预警 / 整改 / 工单"三套话术（参考图中的"未处理告警"在本文档中统一为"未闭环预警"）。
- 三类计数均按**当前数据权限范围**统计；全页面**只在"风险与待办"行展示一处**，不在食堂卡片上重复展示。
- 数值为 `0` 时**保留展示**（显示 0），不做隐藏。

### 5.5 今日运营指标口径

| 指标 | 口径 | 展示 |
| --- | --- | --- |
| 今日营收 | 当日 00:00 至当前时刻的累计营收 | 万元，保留两位小数（如 `¥1.94 万`） |
| 今日就餐 | 当日累计就餐人次 | 人次，千分位分隔（如 `3,230`） |
| 今日投诉 | 当日累计投诉条数 | 条数；`0` 时弱化显示 |

- 三项均为**当日累计**口径，随查询时刻变化；本期不承诺刷新时效（见第 7 章）。
- 三项按**当前数据权限范围**统计：后勤主任为全校各食堂，食堂经理仅本餐厅。
- 三项是**食堂卡片上的横向对比指标**，用于比较各食堂当日表现；**不得与"未闭环预警"互相推导**——投诉是当日发生量，预警是未闭环存量，两者口径不同。
- 与下钻抽屉中的 `本月营收` **口径不同**（日 / 月），不得混用同一份数值。

### 5.6 承包方为空与数据缺失的处理口径（重要）

- **自营食堂没有承包方**：`承包方` 显示 `—`，`合同起止` 显示 `—`，`合同履约状态` 显示"正常"（绿，口径见 5.2）。
- **非自营食堂但承包方数据缺失**：显示 `—`，履约状态显示为 `待确认`，**不得默认按"正常"展示**。
- **口径边界**：本页面的"合同履约状态"仅反映合同期限与终止状态，**不承诺反映合同金额、结算、违约责任等履约质量**；验收时不得按"合同履约全部合规"解读本功能。

## 8. 来源依据

原始需求原文（`platform-view.md`）：

- 平台总览（工作台）：全局运营与工作入口：汇总全校食堂运营情况、经营模式、平台接入情况、系统健康状态、风险待办及公告信息，为用户提供全局概览和核心业务统一入口。

- 平台运行状态：展示平台接入组织、在线网关、设备在线及系统健康情况。
- 公告与快捷入口：展示最新公告，并提供食堂运营、经营分析、合规巡检、中心考核、维修工单、智能预警等核心业务入口。
